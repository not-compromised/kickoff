# Round 3 resolution: M1 facts

Input: `r3-sol-m1-facts.md` (Sol 6.1), a review of commit `4a3a83f`, which recorded the M1 facts in the design. Verdict: no P1, six P2. All six are resolved in the follow-up commit on the same branch. Finding ids R3-1 to R3-6 follow the review's numbering, and the invariants cite them in their "Born from" column.

| Id | Finding | Resolution | Where |
|---|---|---|---|
| R3-1 | Option A does not bound a malicious host's `ServerID`: guest-local destinations bypass pasta, public destinations leak the guest's address, and "HTTPS and DNS" was stated as ports | §3.1.1 is rewritten around two separate problems. **Guest-side validation of every discovery reply is required whatever the fix** (exact type, size cap, canonical JSON against parser differentials, `ServerID` exactly the host's virtual address), so the security problem does not depend on option A or B. A and B now address only the honest-host functional case, decided in M3 after new measurements M1 (p) and (q): guest `ServerID` handling and accepted syntax, Wine address selection per layout, and real LAN-session internet traffic. Egress narrowing is defence in depth and stated as protocols and destinations. Other address-bearing messages are to be investigated before M4. Packet-recorded negative tests cover public, guest-local and forbidden destinations | design §3.1.1, §3.2.5; new SI-42 with two mutants; new class R (§6.2) |
| R3-2 | A Windows guest that accepts a malicious reply sends join traffic over the physical interface | SI-42 validation runs in kickoffd's shared `vlan` path before the service writes to the tap, in every Windows game mode, stock mode included. **Windows multiplayer is gated on SI-42 green on Windows (M7).** An optional WFP block on the game's UDP outside the Kickoff interface during a lease is defence in depth, subject to W1a showing the game needs no internet UDP | design §3.1.1, §3.3, §10 gates, §11; SI-42 scope |
| R3-3 | Parent-death signals and scope stopping do not preserve teardown | §3.2.6 now rests teardown on the cgroup and a surviving owner. The scope is `BindsTo=` the supervisor's service, which is bound to kickoffd's unit, so the user's systemd manager ends it. It is stopped with `KillMode=control-group` and `KillSignal=SIGKILL`, plus a direct `cgroup.kill`, within a 2 s deadline. Parent-death signals are a fast path, each followed by a parent check through a pidfd. The scope is registered before any other process starts. A **final launch barrier**, checked inside and independently from outside, proves namespaces, nft, cgroup membership, rlimits, empty capability sets, `NoNewPrivs` and descriptors before Wine runs. bwrap brings no seccomp or Landlock policy; the kickoffd and `kickoff-parse` policies stay as specified. The tap hand-off is an explicit M3 blocker | design §3.2.6; SI-38 startup-kill test and two mutants; SI-36 launch-barrier test and mutant |
| R3-4 | Testable settings protections were discarded as residual risk; the observe-confirm race was undefined | Kickoff's own behaviour is now **SI-43**: unmodified copies, a freshness check before launch, no settings-editing operation, and guarded automation, tested with filesystem fixtures, a schema test and a fake UI adapter, with three mutants. The race is closed by a single input source during a script, confirmation only on two agreeing observations taken after the last input, and confirm-then-verify. The remaining game-initiated race is stated as residual. Epic's sync stays residual | design §8.6, §6.5; new SI-43; new class S |
| R3-5 | SI-2's and SI-30's new protections lacked removal-sensitive tests | SI-2: a launch-chain stand-in drops, duplicates or substitutes `-noeac` downstream, and unreadable command lines are covered; whole-cgroup termination within 1 s; mutants `no-runtime-cmdline` and `unreadable-allows`. SI-30: the game-log test iterates every registered log-copy path and requires a non-empty sanitized copy with marker lines, so "no copy" fails; mutants `redaction-bypass` and `raw-log-event` | SECURITY-INVARIANTS SI-2, SI-30 |
| R3-6 | The pre-M0 real-account exception had no minimum gate | It is now a named **spike mode**. Prohibited: peers, custom maps, BakkesMod, and handing builds to anyone. Stated limits: no WlFilter (gamescope keeps host clipboard authority), no audio, no kickoffd or Landlock, no seccomp. Mandatory checks before each session cover indirect and direct display authority, descriptor inheritance, teardown and resource limits, broker handling with fake credentials, and install-integrity snapshots. The no-custom-map gate is unchanged | design §3.2.5, §10 gates and M1 row |
